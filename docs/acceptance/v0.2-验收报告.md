## 性能预算（`pnpm e2e:perf`，10 会话 × 约 1155 事件的种子数据，dev 构建）

| 预算 | 实测 | 状态 |
|---|---|---|
| Tab 切换到可操作 p95 < 150ms | 63ms（窗口化前 162ms） | ✅ |
| 发送后本地入队反馈 p95 < 200ms | 95ms | ✅ |
| 10 会话 / 3 活动 Run / 万条消息下输入与滚动流畅 | 打字 40 键、滚动全时间线均无 >50ms 长任务 | ✅ |

注：数字来自 dev 构建（未压缩 React），且每次轮询含 CDP 往返开销，是偏保守的上界；生产构建只会更快。时间线已改为尾部窗口渲染（挂载只渲染最新 100 项，上滑加载更早），这是达标的关键改动。

## 已知限制（v0.2）

1. **Codex 的 MCP 工具调用每次都需权限卡确认**：codex 提供 persist（session/always）但响应形状未验证，v0.2 只提供「允许一次/拒绝」（ADR 0020 §4）。
2. **pi 无权限门控**：pi 的 RPC 模式没有审批事件，写入安全依赖 worktree 隔离；协作工具经 `pi -e` 原生拓展注入。
3. **上下文超预算 / 磁盘写入失败**没有专门的状态与恢复 UI：统一表现为 `run.failed` + 重试按钮，错误文案来自 harness 原文。
4. **契约测试（真实 CLI）未常态化**：`pnpm test:contract` 耗真实额度，只在版本升级前后手动运行；能力矩阵与 fixtures 固定的是 codex 0.154.0 / pi 0.84.2 / Claude Agent SDK 当前版本。
5. **dsh 接入暂缓**（2026-11-07 起）：可检测但不出现在 UI。
6. **托盘与系统通知未实现**（plan §10.5 列为可选）。
7. **macOS 签名公证暂缓**（2026-11-18 决定）：`pnpm pack:mac` 产出未签名 .app，内测分发需右键打开；证书到位后的步骤见 `docs/distribution.md`。

## 安装包

`pnpm pack:mac` 产出未签名 `.app`（`packages/desktop/release/`）。内测机首次打开：右键 → 打开。签名公证与独立设备验证是 v0.2 发布前的最后一步，依赖正式产品名与 Apple Developer 证书两个外部决定。
